# Speculative Decoding

Speculative decoding uses a smaller, faster "draft" model to generate draft tokens and then a larger "target" model to verify them. This can significantly speed up generation, especially for models with high VRAM bandwidth.

**Configuration:**

Specify a `speculative_model` and adjust `num_speculative_tokens`.

**Python (`LLM` class):**
````python
# Use a smaller model for speculative decoding
llm = LLM(
    model="meta-llama/Llama-2-70b-hf",
    speculative_model="TinyLlama/TinyLlama-1.1B-Chat-v1.0",
    num_speculative_tokens=5,
    tensor_parallel_size=4, # Ensure the main model fits
    trust_remote_code=True,
)
````

## How it works?

Speculative decoding accelerates generation by using a small, fast "draft model" ($M_d$) to propose candidate tokens and a large, powerful "target model" ($M_t$) to validate them. This reduces the number of sequential, expensive forward passes required from the target model.

The core idea is based on a modified rejection sampling scheme.

1.  **Drafting Phase:** Given a prompt (prefix) $x_{1..n}$, the draft model $M_d$ autoregressively generates a sequence of $\gamma$ draft tokens, $\tilde{x}_{n+1}, \tilde{x}_{n+2}, \ldots, \tilde{x}_{n+\gamma}$. This is fast because $M_d$ is small.

2.  **Verification Phase:** The target model $M_t$ takes the combined sequence of the original prompt and all the draft tokens ($x_{1..n}, \tilde{x}_{n+1}, \ldots, \tilde{x}_{n+\gamma-1}$) as a single input. It performs one forward pass to compute the probability distributions for the *next* token at each position in parallel. This gives us:
    $$
    p_t(\cdot | x_{1..n}), \quad p_t(\cdot | x_{1..n}, \tilde{x}_{n+1}), \quad \ldots, \quad p_t(\cdot | x_{1..n}, \ldots, \tilde{x}_{n+\gamma-1})
    $$

3.  **Acceptance/Rejection Phase:** Each draft token is validated sequentially. For the $j$-th draft token $\tilde{x}_{n+j}$, it is accepted if a randomly drawn number $r \in [0, 1]$ satisfies:
    $$
    r \le \frac{p_t(\tilde{x}_{n+j} \mid \text{prefix})}{p_d(\tilde{x}_{n+j} \mid \text{prefix})}
    $$
    where `prefix` includes the original prompt and any previously accepted draft tokens.

    -   If $p_t(\tilde{x}_{n+j}) > p_d(\tilde{x}_{n+j})$, the draft token is very likely to be accepted.
    -   If $p_t(\tilde{x}_{n+j}) \le p_d(\tilde{x}_{n+j})$, the token is accepted with a probability equal to the ratio of the probabilities.
    -   This process stops at the first rejected token, $k+1$. All subsequent draft tokens are also discarded.
    - Example if $p_t(token)$ is 0.3 and $p_d(token)$ is 0.8. Here the draft model is more confident than target model so here let's say we r = 0.5. Then 0.3 / 0.8 = 0.375 here it will be rejected. This ensures the generation is same quality as target model without lossing speed. 

4.  **Correction and Finalization:**
    -   If $k$ tokens were accepted, the final sequence is now the prompt plus these $k$ tokens.
    -   A final token is then generated by sampling from a "corrected" probability distribution, which is derived from the difference between the target and draft model probabilities at that position: $p_{new} \propto \max(0, p_t - p_d)$. This ensures the overall distribution of generated tokens matches the target model $M_t$.
    -   The process then repeats from this new, longer sequence.
